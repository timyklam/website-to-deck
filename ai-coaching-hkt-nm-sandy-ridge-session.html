Two Blog Posts, One Story: Building a Unifying Deck

In this session we gave the agent two HKT blog posts — the Northern Metropolis 2026 update and the Sandy Ridge Data Park explainer — and asked for a single branded deck that tells one unifying story with HKT's role at the centre. New moves this time: parallel background captures, a merged asset set, a self-driven headless visual-QA loop, and five new lessons written back into the skill.

2 blog posts merged into one arc

live on GitHub Pages

1The brief and the story arc

Two URLs, one instruction: "build a deck that combines both blog posts in a unifying story that highlights HKT's role."

1 · Parallel captures ~2 min

Both pages captured simultaneously in the background (nohup … &) while the agent webfetched both posts' full text in parallel — the story was outlined before the screenshots finished.

2 · One narrative —

Not two mini-decks. One arc: NM = the plan → Sandy Ridge = the compute centerpiece → HKT = the network already in the ground, bridged with "HKT's role · part one / part two" kickers.

3 · Merged assets ~1 min

The richer capture became the deck's capture/ root; only the second post's unique image was copied across, then the duplicate capture dir deleted. One portable asset tree.

4 · QA + publish ~5 min

Every slide screenshotted headlessly (no test framework needed), fixed across 3 rounds, then gh repo create → Pages API → live URL verified with curl.

2The visual-QA loop — this time the AI caught its own bugs

Instead of waiting for human feedback, the agent screenshotted all 10 slides headlessly and read its own output. Three defect rounds were found and fixed before delivery. Screenshot-driven self-review is the skill to learn.

Round 1 · Baked-in text

Hero image fragments: "…polis", "…gy & Update"

First render: the pre-branded og-image's baked-in caption leaks into the frame as cropped fragments.
Final: object-position + scale(1.34) pushes the caption band off-frame; city and network lines stay.
TrapThe social card looked like the perfect hero — until edge fragments of its baked-in text appeared at 16:9.
FixCropped with object-fit:cover + transform:scale() — and learned it takes more zoom than expected, verified by screenshot across 3 iterations.
Round 2 · Dead space

A stats row pinned to the bottom left the middle of the slide empty

Full-width layout: copy up top, four stat cards stranded at the bottom.
Final: two-column rebalance — narrative left, 2×2 stat grid + source note right.
Rule reinforced: fill white space by restructuring (columns, distribution), not by shrinking gaps — a full-width stack with margin-top:auto is a dead-space generator.
Round 3 · Balance + restraint

A gap band on slide 9, and a watermark that shouted on slide 10

Dark closer-arc slide: cards top, quote pinned bottom, nothing between.
Final: content group flex-centered, proof chips added, quote anchored — and slide 10's watermark dialed to opacity .16 / stroke .3.
LessonDecoration has a dial: a network watermark at opacity .3 with .9 stroke read as "bold graphic"; at .16/.3 it reads as texture.
FixWrapped cards + chips in one flex:1 centered column, then tuned the watermark in two passes.

3Five new lessons — written into the skill permanently

Pushed to the website-to-deck repo as commit 3d832c7, so every future deck starts here.

Multi-post unifying decksCapture each URL in parallel to its own dir; keep the richer capture as the deck's asset root, copy only needed extras, delete the rest. One arc, bridge kickers, sources cited on title AND closer.
og-image.jpg is a hero assetThe social card is often the best pre-branded ~1200×627 image in the capture — crop its baked-in text with object-position + scale, verify by screenshot.
Headless slide QA loopsed-injected hash-jumper + headless Chrome per slide (--virtual-time-budget=3000), run from the project dir so relative assets resolve. Re-render only changed slides.
SVGs don't render in image readsVerify logo candidates with qlmanage -t PNG previews + inline-SVG cross-check from page.html — file size and viewBox alone aren't proof.
Link gate vs relative hrefsCaptures store /contact-us style paths, so absolute URLs false-REVIEW. Grep the path form — and the right page.html when merging two captures.
Layout bugs never show in code reviewEvery slide gets screenshotted and read before delivery — clipped crops, dead space, and over-bold watermarks are invisible in the diff.

4Guardrails that held

  • Quoted copy only — every stat (300 km², 180,000 PFLOPS, HK$23.8B, 36×) traces to the captured posts; nothing invented to bridge the two stories.
  • DOM-verified links — contact, blog and AI SuperHighway URLs grepped against the captured HTML (path-form match, not guessed patterns).
  • Real brand assets — HKT wordmark extracted from the DOM and verified via PNG preview; zone map, aerial hero and og-image are the site's own files.
  • Publish checks — Pages build status built via API, live HTML curl-checked, asset 200-verified before handover.

6Takeaways for your next AI session

  • Multi-source briefs work when you name the angle. "Combine both posts in a unifying story that highlights HKT's role" gave the agent the arc — it built the bridge, not two summaries.
  • Ask the AI to review its own screenshots. "QA every slide headlessly before showing me" turns visual regressions into a 2-minute self-fix instead of a feedback round.
  • Run waits in parallel. Two background captures + two webfetches meant the content plan was done while the captures ran.
  • Before/after beats description. When a fix is subtle (crop, spacing, opacity), screenshot the before and after — the diff is the proof.
  • End every session with the learning write-back. "What new lessons go into the skill?" — then push them, so the next deck starts ahead.
