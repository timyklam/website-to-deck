What was built

Upstream anonymized each cell independently with random Faker output — "peter pan" became a different name every occurrence and every run. The patch makes replacements deterministic and reusable: one original value → one fake value, forever.

normalize cell→ lookup key in mapping.json→ hit? reuse : seed-fake & store→ write back in-place (openpyxl)

Column fallback for *name* / *tel* headers; fixed 1:1 date remap; digit-shape-preserving numeric IDs; namespace bridging for phone/card/IDs; gitignored mapping.json doubles as the (secret) de-anonymization key.

The learnings

1 · "Random per cell" is the default of NLP anonymizers — determinism is an add-on you must design

Presidio+Faker pipelines call the generator once per detection. Consistency required three deliberate pieces: a memoized lookup (original→fake within a run), a persistent store (across files/sessions), and a seeded Faker (reproducible new entries).

Why it matters: analytics on anonymized data (join counts, deduplication, referential integrity) is only possible if identical inputs collapse to identical outputs.

2 · The mapping key is everything — normalize before you memoize

"Peter Pan", "peter pan", "PETER.PAN@EXAMPLE.COM", "(555) 123-4567" vs 5551234567 — naïve string keys would mint a different fake for each surface form. Keys are canonicalized (casefold, whitespace, digits-only) so all forms share one entry; dates normalize to ISO.

Why it matters: case-insensitive keys were a deliberate choice — "CYRUS FAN" and "Cyrus Fan" should be the same person. But it also means "Peter Pan" vs "peter pan" cannot intentionally get different fakes. Know which equivalences you want.

3 · Entity types leak into each other — bridge the namespaces or split identities

The same digits arriving as text "5551234567" vs numeric 5551234567 initially landed in different namespaces (PHONE vs ID) and got two fakes. A bridge layer now resolves any digit string across PHONE/CARD/ID namespaces before minting a new fake.

Why it matters: real spreadsheets store the same value in multiple types across columns and sheets; type-rigid mapping silently breaks row-level linkage.

4 · NER models are built for prose, not spreadsheets — recall gaps are structural

On real data, Presidio+spaCy missed: ALL-CAPS names ("CYRUS FAN"), company names (no ORGANIZATION operator in use), and 8-digit local phone numbers ("2883 8760"). These are structural failures of trained-on-articles models, not tuning bugs.

Why it matters: the robust fix for tabular data is column-header-driven fallback (*name* → treat whole cell as a name, *tel* → phone), routed through the same mapping. NLP becomes the fallback, not the primary — inverting the original design.

5 · Detectors also misfire — validate the entity, not just detect it

Presidio classified "Card 4111111111111111" as a PERSON, so the card number was replaced with a person name and its mapping key diverged from the same card elsewhere. Guard: spans typed PERSON/LOCATION but containing long digit runs get re-processed digit-run-wise, with Luhn validation deciding card vs plain ID.

Why it matters: in anonymization pipelines, a detector error is worse than a miss — it can silently corrupt consistency while appearing to work.

6 · Test fixtures are a data-leak vector — audit before you push

The pre-push cleanliness audit found real customer names and phone numbers embedded in test fixtures — copied from master.xlsx for realism and then nearly pushed to GitHub. All fixtures were scrubbed to synthetic data, and .gitignore now hard-blocks mapping.json, *-anonymized.xlsx, and master*.xlsx.

Why it matters: de-identification work has a habit of re-importing the very data it protects. Defense-in-depth (scan tree and git history, gitignore the outputs, keep sidecars outside the repo) beats one-time diligence.

7 · Environment reality checks come before code

Python 3.14 had no spaCy build → venv pinned to 3.11; en_core_web_lg is absent from PyPI (upstream packaging quirk) → installed via spacy download. A 10-second sample benchmark (2 ms/cell) de-risked the full 11,730-cell run before committing to it.

Why it matters: measure the per-unit cost, extrapolate, then run — cheap insurance against a 40-minute surprise.

Chapter 2 — the improvement brief (v2)

8 · An external AI brief is a code review in disguise — triage it against the code, not the prose

A second AI produced a 300-line improvement brief. ~70% described features already implemented (it had evidently read the upstream repo, not our patch). The valuable 30%: a real latent bug (collision retry gives up after 10 tries then accepts duplicates), a sharp critique of global Faker.seed() being traversal-order-dependent, phone +CC/00CC prefix equivalence, .xlsm/keep_vba, and token mode.

Why it matters: adopt the brief's defects list, negotiate its design opinions (ephemeral-by-default contradicted the user's explicit cross-file requirement; encrypted store was deferred as YAGNI).

9 · Token mode: PERSON_000001 is a better default than realistic fake names

Counter-based tokens are collision-proof, order-independent by construction, obviously fictional (no risk of inventing a real person), and trivially auditable. Emails render as person000001@example.test (reserved TLD); phones/cards keep digit shape; custom entities support format-preserving tokens (HK-2026-00142 → HK-8803-15604).

Why it matters: Faker can accidentally generate a real person's data; tokens never do.

10 · Order-independent determinism needs per-key seeding, not a global seed

Faker.seed(n) is sequence-dependent: reordering rows/sheets changes every subsequently minted fake. Replacement: seed per key via HMAC(secret, "TYPE|canonical"). Bonus trap discovered the hard way: constructing a fresh Faker() per cell costs ~100-300 ms — the test suite hung for 15 minutes. Reseed one shared instance.

Why it matters: same logical content must map identically regardless of layout; a global seed silently violates this.

11 · Span merging: rules beat NLP, longest wins, never re-scan replaced text

Custom regex entities (matter IDs) and Presidio spans must be resolved into one overlap-free span list (custom wins, then longest), replaced right-to-left against the original string. Re-running NLP on already-tokenized text mangles inserted tokens into new entities — e.g. a token inside an email address.

Why it matters: free-text cells routinely mix domains: "See HK-2026-00142 regarding Peter Pan" needs both detectors on one consistent pass.

12 · Small-tool classics that still bite

filename.rstrip(".xlsx") strips the character set {.,x,l,s} — "ns.xlsx" became "n" and a test phantom-failed for an hour (use Path.stem). Greedy header heuristics: "Customer ID" matched the "customer" org pattern until id-ish headers got an exclusion check. Shape-preserving digit generators must reject fake == original.

Why it matters: every one of these was caught by a test, not by inspection — the suite pays for itself constantly.
