From Website URL to Live Sales Deck in One Session

A real working session, unedited: we pointed an AI coding agent (opencode) at the HKT China Connectivity Solutions web page and asked for a branded, boardroom-ready HTML deck — then art-directed it through four rounds of visual feedback, and published it to GitHub Pages. This is the playbook you can repeat for any product page.

7 web pages read & quoted
~40 min idea → live URL
0 invented claims

1The workflow the AI followed

A repeatable 4-step pipeline (the agent has this saved as a reusable "skill").

1 · Capture ~4 min

A headless browser screenshots the page, downloads 45 real assets (logo, photos, fonts) and extracts design tokens: colors #012F56 / #0085FF / #10C7F1, typography, section map.

2 · Look ahead ~2 min

While the capture ran, the agent read 6 linked pages in parallel — the Chow Tai Fook case study and all 5 product pages — so extra slides quote real downstream copy, not padding.

3 · Build ~5 min

One self-contained deck.html: 1280×720 stage, keyboard navigation, per-slide entrance animations, relative asset paths. Every text is quoted from the captured pages; every outbound link greps back to the captured DOM.

4 · Publish ~2 min

git init → gh repo create → GitHub Pages build verified via API → live URL. Stale-CDN gotcha handled with a cache-bust check.

2The fine-tuning loop — where the human adds the value

The first draft was structurally right but visually imperfect. Four rounds of precise, visual feedback took it to boardroom quality. This loop is the skill to learn.

Round 1 · Watermarks

“Most of the SVGs are too big and overlap the texts”

Slide 12 as delivered: the decorative shield mark runs straight into the body copy.
You saidShort, specific, no markup knowledge needed — just what looks wrong.
AI didShrank all watermark SVGs ~40–65%, pushed them off the card corners, dropped opacity 0.85 → 0.4.
Round 2 · Clipping

“New problem: the SVG got cut off after your change”

You saidOne line — the fix created a new defect. Catching regressions is your job, not the AI's.
AI didRealised pushing marks off-corner meant clipping; placed them fully inside the bottom-right corner instead.
Pattern: AI fixes are local — each round solves the named problem and can break a neighbour. Review the whole slide after every round.
Round 3 · Layout

“Expand the height of all these boxes to accommodate the SVG”

The screenshot you attached: the icon needs breathing room the text box doesn't give it.
You saidDon't just move the decoration — change the layout so both elements fit.
AI didGave tiles a 106px min-height, centered text vertically, indented copy 30px clear of the icon zone; same treatment for all card types.
Round 4 · Wrong asset + overlap

“Fix the upper right corner on slide 8 … still problematic — redo the page”

Root cause: the "photo" was actually an icon PNG — object-fit blew it up into a giant globe.
First fix swapped the asset but overlapped icon and caption — so you asked for a redo.
You said“Redo the page” — a clear escalation when incremental patching isn't converging.
AI didRebuilt the panel as a flex column — icon centered in its own zone, caption in its own bar — two regions that physically cannot collide.

3The AI learned too — permanently

Each fix was written back into the agent's reusable website-to-deck skill, so the next deck starts from these lessons instead of repeating them.

Watermark sizing rulesIn cards under ~180px tall: 40–60px icons, fully inside, 45% opacity, min-height on the card + text padding clearance.
Icon PNGs aren't photosCaptured "image" assets that are flat glyph icons get replaced with gradient panels + inline stroke SVGs — never object-fit:cover'd.
Flex panels can't collideIcon zone and caption bar as separate flex rows, never absolutely positioned over each other.
Look-ahead economicswebfetch (~10s) for text-only slides vs full capture (~2 min each); run captures in the background while fetching in parallel.

4Guardrails that made it safe to publish

  • Quoted copy only — every headline and bullet traces back to the captured page text; the AI was never allowed to invent claims.
  • DOM-verified links — all 7 outbound URLs were grepped against the captured HTML, not guessed from URL patterns.
  • Real brand assets — the HKT logo, GBA skyline, use-case photos and CTF storefront are the site's own files, downloaded locally.
  • Publish checks — Pages build status verified via API and the live URL curl-checked before being handed over.

6Takeaways for your next AI session

  • Give the AI a URL and an outcome, not instructions. "Turn this page into a deck and host it" is a complete brief — the skill carries the how.
  • Ask it to look ahead. "Pull the case study and sub-pages in" is what separated 5 thin product cards from 5 deep-dive slides quoting real copy.
  • Feedback in sight, not in code. A screenshot + one sentence ("this overlaps") beats a CSS lecture every time.
  • Catch regressions ruthlessly. Every fix is local; re-check the whole slide, and escalate ("redo the page") when patching stops converging.
  • Make lessons permanent. End the session by asking the AI to write its own mistakes into the skill — your second deck will need half the rounds.
  • Demand verification before publish. Asset paths, outbound links, build status — the same checks a human reviewer would do, done by the agent on request.
